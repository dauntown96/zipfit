# 네트워크 허용 목록 — 클라우드 환경 「Default」

> 2026-10-14 신설 (우편함 「코드 — 표지 일정 칸 … · 허용 목록 점검 장치 …」 3 · 조사·의견 「허용 도메인」 회신 ⑦ 채택).
> 왜: 같은 도메인이 하루에 「000」·「403」·「열림」으로 세 번 다르게 기록됐고(2026-10-13 `CLAUDE.md` 「000」 ↔ 2026-10-14 403·200), 회신마다 낡은 기록을 인용했다.
> 그래서 「열렸나」를 기억에 적지 않고 **세션마다 이 표를 다시 불러 본다** — `.claude/hooks/session-setup.sh`가 아래 표의 도메인을 한 번씩 불러 `/tmp/zipfit-session-setup.log`에 남긴다.

## 🔴 판별 규칙 — 결과를 읽는 법

| curl 결과 | 뜻 | 축 |
|---|---|---|
| `CONNECT tunnel failed, response 403` (`%{http_connect}` = 403 · `%{http_code}` = 000) | **우리 환경의 허용 목록이 막았다** | 허용 목록 축 — 다운님이 설정에 한 줄 더하면 열린다 |
| 서버 응답(200 · 301 · 302 · 400 · 401 · 403 · 404) | **열림** — 서버까지 닿았다(루트 경로라 404·400도 정상) | — |
| `000`인데 CONNECT는 200(시간 초과 · `Connection reset by peer`) | 판정 보류 — 터널은 열렸고 서버 쪽이 끊었다 · 한 번 더 부른다(스크립트가 저절로) | 서버·기관 축(해외 IP 차단 · 기관 서버 불안정) |

- ⚠️ 서버가 돌려준 403(`t1.kakaocdn.net` 루트 등)은 **열림**이다 — 허용 목록 403은 언제나 CONNECT 단계에서 나고 `%{http_code}`는 000이다.
- 🔴 **해외 IP 축은 허용 목록에 넣은 뒤에야 보인다** — 허용 목록이 막는 동안에는 서버까지 가지 않는다. 해외 IP를 막는 기관은 서울 지역 EF(`SEOUL_ONLY` — 부산도시공사 선례)나 claude.ai(다운님 PC)로 돌아간다.
- 허용 목록은 클라우드 환경 「Default」 **하나**이고, 다운님이 여는 Claude Code 세션과 감지 루틴이 **같이 쓴다**. 설정을 바꾸면 **새 세션부터** 먹는다(조사·의견 「허용 도메인」 회신 ⓐ).
- 이 목록과 무관한 길: GitHub(별도 프록시) · MCP 커넥터(Notion·Supabase·Drive 등) · 환경 network secret 호스트(`api.supabase.com`) · Supabase EF·DB의 `net.http_*`(싱가포르 · EF는 서울 실행 가능) · GitHub Actions.
