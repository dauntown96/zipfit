## 2. 펼침 꼴 둘 — 블록 공고 「단지 칩」 ↔ 매입임대 「건물별 묶음」

### 사실

- 갈림 자리: 카드를 펼치면 `get_announcement_sites`(없으면 `get_announcement_blocks`)를 부른다(`index.html` 10153행 부근). **2건 이상**이면 블록 경로 — 머리 「🏘️ 이 공고에 포함된 블록 (N개)」 + 단지 칩 줄(`zf-site-pick` · 10215행) + 블록마다 `loadHousingUnits(…, '카드id-blk{n}')`. **1건 이하**면 한 칸 경로 — `loadHousingUnits` 한 번 → `groupHousingUnits`(건물 `building_name`, 없으면 주소로 묶음) → 건물이 둘 이상이면 건물 머리 목록(`hu-group-head` · 누르면 펼침 · 「더 보기 (건물 N개 더)」), 하나면 머리 없이 바로 세대 행.
- 블록은 「같은 제목 그룹 안에서 주소·세대수가 다른 원본 행 / 단지명(`site_label`)」이고, 매입임대는 원본 행 하나 안에 여러 건물(주택)이 세대 행으로 들어 있다 — 데이터가 서는 축이 다르다.
- 열린 91건(16:49 KST) 셈: 블록 ≥ 2 = **30**(국민임대 23 · 영구임대 4 · 행복주택 3 — 모두 건물도 ≥ 2) · 블록 1 · 건물 ≥ 2 = **6**(매입임대 4 · 국민임대 1 · 수요자맞춤형 1) · 블록 1 · 건물 1 = 50 · 세대 행 0 = 5(전세임대 4 · 새 행복주택 1).

### 한 부품으로 맞추면 깨지는 것

- 블록 경로만 가진 것: 블록별 회차 판정(「다른 회차 · …」 배지 · 「이번 회차 블록 정보는 아직 없어요」) · 블록 모집 합(`fetchBlockRecruitSums`) · 「단지 구분 전 전체」(`blockHuFallback`) · 지도 활성 블록(`zfBlkActive` — 빠르게 번갈아 열 때 지도 되돌림 막음) · 단지 모양(같은 ID + 단지명 축 · `zfSiteFilter`).
- 한 칸 경로만 가진 것: 건물 「더 보기」 10개 단위 · 건물 머리의 📷 칩 키(건물 이름) · 건물 1개면 머리 생략.
- 데이터 경로를 하나로 합치면 위 다섯이 매입임대에는 뜻이 없고(회차·모집 합이 건물 축에 없음), 블록 공고에는 건물 묶음이 한 겹 더 생긴다(블록 안에 다시 건물 머리 — 지금도 블록 안에서 `groupHousingUnits`가 돈다).

### Claude Code 의견

- 좋은 점: 두 꼴 모두 데이터 축을 정직하게 따른다(블록 = 원문 단지 · 건물 = 매입 주택).
- 걱정: 사용자에게는 둘 다 「이 공고 안의 여러 집」인데 겉모양이 칩 줄 / 머리 목록으로 달라 같은 동작을 두 번 배운다.
- 권하는 안: **데이터 경로는 둘 그대로 두고 겉모양만 한 부품** — 매입임대 건물도 「건물」 칩 줄(칩 = 건물 이름 · 누르면 그 건물 세대)로 그리고, 블록 칩과 같은 칩 부품을 쓴다. 건물 수가 많은 매입(수십 채)은 칩 줄이 길어지므로 「더 보기」 대신 가로 밀기 + 개수.

## 3. 세대 아코디언 — 「하나 = 접을 수 없는 펼침 · 둘 이상 = 접힘」

### 사실

- 자리: `renderHousingUnitGroup`(`index.html` 12034~12042행 부근). 주택형(`unit_group`) 묶음 안의 **화면 줄 수**(계층 라벨 · 금액 네 칸 · 동호수 · 회차가 완전히 같은 행은 한 줄로 합친 뒤)가 1이면 `div.hu-ug-one`(머리 + 그 줄 · 접는 칸 없음), 2 이상이면 `<details class="hu-ug">`(`open` 없음 → 처음에 접힘).
- 들어온 때: 줄 하나 = 펼침은 PR #1093(2026-11-17 「표시층 — 작은 판 2」 3). 둘 이상 = 접힘은 `details`에 `open`을 달지 않은 종전 그대로.
- 기준은 「계층 수」가 아니라 「합친 뒤 화면 줄 수」다 — 계층이 하나라도 금액이 둘이면(두 임대조건 · 층별 금액) 접히고, 계층이 둘이라도 화면 값이 완전히 같으면 한 줄로 합쳐 펼쳐진다.
- ⚠️ CSS 주석(441행)은 「머리줄은 접을 수 있고 기본은 펼침」이라 적혀 있다 — 지금 동작(둘 이상 = 접힘)과 다르다(문서 낡음 · 고치지 않음).

### 「모두 접힘 + 머리 줄 대표 금액·계층 수」 안에 대한 의견

- 좋은 점: 줄 수에 따라 꼴이 바뀌지 않아 한 공고 안 묶음들이 같아 보인다 · 머리만 훑어 주택형끼리 금액을 견줄 수 있다.
- 걱정: ① 줄 하나 묶음을 다시 접으면 #1093이 이틀 전 줄인 「금액 보려고 한 번 더 누름」이 되돌아온다. ② 머리 「대표 금액」을 한 값으로 고르면 원칙 37(숫자는 원문 그대로)과 부딪친다 — 중앙값·최소값 하나는 원문에 없는 대표다.
- 권하는 안: 머리 줄 = 「보증금 a~b · 월 c~d · 계층 n」(묶음 안 원문 값의 범위 — 줄 하나면 그 값 그대로) · 묶음이 **하나뿐인 공고는 펼침**, 둘 이상이면 모두 접힘. 그러면 줄 하나 묶음도 머리에 금액이 이미 있어 접어도 누를 일이 없다.
- 제안 시점: S1 — 2와 같은 상세 단계.

## 4. 필터 시트 안 「공고 유형」 — 바깥 바로가기와 두 곳

### 사실

- 상태는 **한 곳**이다 — `activeNoticeType` 하나, 칩도 시트의 `#noticeTypeChips` 하나. 바깥 「유형 바로가기 줄」(`zf3TypeRow` · 15207행 부근 · 2026-11-18 디자인 2차 1단계)은 그 칩을 읽어 그리고, 누르면 그 칩을 `click()`한다(15943행 부근 — 「거름 규칙 새로 0 · 선택 상태도 그 칩 하나」 주석).
- 그래서 보이는 자리는 둘이지만 상태 사본은 없다. 두 곳에 둔 까닭은 1단계가 시트를 그대로 두고 바로가기를 **덧붙인** 것(시트 안 칩 = 원천).
- 시트에서 빼면:
  - **요소째 지우면** 깨진다 — 바로가기 줄이 칩 목록을 못 읽어 사라지고(`chips.length < 2`면 줄을 안 그림), 누름이 갈 곳이 없다. `resetNoticeFilters` · 조건 칩 ✕(14972행) · 화면 복귀(3658 · 14293행)의 `refreshChipSel('noticeTypeChips', …)`는 요소가 없으면 조용히 넘어간다(오류는 없음).
  - **보이지 않게만(그 칸 `field`를 숨김)** 하면 깨지는 것 없음 — 필터 개수 배지(`data-act="sheet"` 버튼의 숫자)는 조건 칩 목록에서 세므로 그대로 · 초기화 그대로.
  - 1280: 바로가기 줄·시트에 넓은 화면 전용 규칙이 없다(같은 머리 `#zf3NoticeHead`) — 390과 같다.

### Claude Code 의견

- 좋은 점: 상태 하나라 두 곳이 어긋날 수 없다.
- 걱정: 시트를 연 사람은 같은 칩 줄을 두 번 본다(바깥 줄과 시트 맨 위) — 시트가 길어지고 「여기서 고르면 바깥과 다른가」를 묻게 한다.
- 권하는 안: 시트의 「공고 유형」 칸을 **숨기고**(요소는 원천으로 남김) 시트 맨 위에 「유형은 위 줄에서 골라요」 한 줄 — 또는 숨기지 않고 지금 고른 유형만 한 줄 요약. 요소 삭제는 하지 않는다.
- 제안 시점: S1 — 디자인 2차 다음 단계(표시층 · 작음).

## 5. 「조건별 다름」 — 열린 공고 셈과 갈래

### 사실

- 자리: 카드 겉 금액 줄(`zf12Price` · 16216행 부근) — 요약 칸에 `.zf-dual-tag`가 있으면 「· 조건별 다름」. 표지 재료(`zfEnsurePriceSummaries` · 6183행 부근): ① 세대 행에 `deposit_priority1`·`rent_priority1`이 있으면 「두 임대조건」 ② 세대 행 `supply_target`에 가군·나군이 둘 다 있으면 「가군·나군」 ③ 「N구간」이 둘 이상이면 「소득 구간」(②③은 금액이 범위일 때만).
- 열린 91건(16:49 KST): **18건** — 두 임대조건 4(경기북부 신혼·신생아 매입 Ⅰ·Ⅱ · 마포 신혼부부·청년 · 장성 국민임대) · 가군·나군 12(영구임대 11 · 인제서화 고령자복지 영구 1) · 소득 구간 2(평창장평 통합공공 일반형·고령자복지형 · 1~6구간). 나머지 73건은 붙지 않음.

### Claude Code 의견

- 좋은 점: 범위가 넓은 까닭이 있다는 신호를 한 낱말로 준다.
- 걱정: 세 갈래가 모두 같은 말이라 「무엇이」 다른지 안 보인다 — 영구임대 12건은 「가군·나군」이라 금액이 군으로 갈리는데, 「조건별」은 사용자가 자기 조건(소득 등)으로 읽기 쉽다.
- 권하는 안(짧은 꼴 · 원문 낱말): 「· 두 조건」 / 「· 가·나군별」 / 「· 소득 구간별」 — 펼친 상세의 설명(title 글)은 지금 그대로.
- 제안 시점: S1 — 문구 고침이라 디자인 2차 어느 단계에 얹어도 됨.

## 6. 카드 겉 지역 자리 · 알약 자리 (의견 한 줄)

- 표시층 4단계 덧으로 시안이 나오므로 의견 한 줄: 지역은 「시·도 + 시·군·구 하나」로 줄이고(여러 곳은 「외 N곳」 — 지금 매입 카드 꼴), 알약은 상태 하나 + 경고 하나까지만 겉에 두고 나머지는 펼친 뒤로 — 2·3의 「같은 동작은 한 부품」과 같은 축.
