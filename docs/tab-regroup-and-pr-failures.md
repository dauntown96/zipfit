## Claude Code 의견

**좋은 점**
- 실패는 몇 갈래에 몰려 있다. 표 칸 `|`(10)와 이력 두 파일 충돌(42 · 40)을 막으면 14일치 빨간 check와 충돌의 대부분이 사라진다. 나머지(불변식 · 사본 md5 · visual)는 장치가 제 일을 한 것이라 막을 대상이 아니다.
- ①의 공고일·정정일 손실은 원인이 CSS 한 줄로 좁혀져, 고칠 때 되돌림이 작다.

**걱정**
- (다)는 규칙 문서 여러 곳(`CLAUDE.md` 원칙 13 · 21 · 「최근 작업 이력」 · ⑦ · 스킬의 이력 쓰기 단계)을 함께 바꿔야 한다. 하나라도 남으면 옛 꼴과 새 꼴이 섞인다. 루틴(자동 분석)도 이력을 쓰므로 스킬까지 같은 회차에 바뀌어야 한다.
- 「잡 0개 실패」(db 6 · unit10 7)는 「시각 회귀 기준 갱신」 커밋과 같은 초에 다섯 워크플로가 함께 떨어진 것이다. 원인을 못 봤고, 후보 표 밖이다.
- `screen`이 필수 체크가 아니라 9 PR이 초록 run 없이 병합됐다. 실패 막기와 결이 다르지만 「병렬이라 실패가 잦다」는 체감에 섞여 있을 수 있다.
- ①은 표본 10장·밝음만 봤다. 어두움·저장 목록·맞춤 결과(같은 `zf12Front`를 탄다)는 재지 않았다.

**권하는 안**
1. **(가)부터 — 이번 주.** 저장소 스크립트 하나로 `check`의 문서 검사를 push 전에 돌리고, `CLAUDE.md` 컨테이너 메모 한 줄로 부른다. 드는 일이 가장 작고 표 칸 10건을 바로 막는다.
2. **(다)는 규칙 회차로 — claude.ai·다운님 판정 뒤.** `CLAUDE.md` 「최근 작업 이력」 표를 걷고 `docs/history.d/` 파일로 옮기면 충돌 82(두 파일 합)가 구조적으로 0이 된다. 봇은 두지 않는다.
3. (라)·(마)는 하지 않는다. 효과(3 · 2건)보다 바뀌는 길(배포 · 승인 근거)이 무겁다.
4. ①의 2·3·4는 「표시층 — 회귀 고침」과 같은 꼴(한 줄)이라 그 회차에 이어 붙이기를 권한다. 다만 공고일·정정일을 겉 줄로 되돌릴지, 상세 칸만 살릴지는 디자인 판단이다.
